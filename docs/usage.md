# 使用指南

## 基本用法

### 升级 Go 版本

```bash
# 在当前目录查找 go.mod
go-mod-select 1.25

# 指定工作目录
go-mod-select 1.25 --dir /path/to/project

# 指定 go.mod 文件路径
go-mod-select 1.25 --gomod /path/to/go.mod
```

### 命令行参数

| 参数 | 说明 |
|------|------|
| `version` | 目标 Go 版本（位置参数） |
| `--dir` | 工作目录（在此目录查找 go.mod） |
| `--gomod` | 直接指定 go.mod 文件路径（文件名必须是 `go.mod`，与 `--dir` 互斥） |
| `--dry-run` | 仅查看可更新模块，不执行更新（与 `--auto` 互斥） |
| `--auto` | 自动选择并应用所有兼容更新（非交互模式） |
| `--allow-downgrade` | `--auto` 模式下同时应用降级（默认跳过，见下） |
| `--verbose` | 显示详细输出 |

### 工作模式

**三种模式优先级**：
1. **--gomod** 参数（最高） - 使用指定的 go.mod 文件。文件名必须是 `go.mod`：go 命令从所在目录推断模块根，无法被重定向到别名文件，否则会出现"编辑 A 文件、`go get` 却操作 B 文件"的错配
2. **--dir** 参数 - 在指定目录查找 go.mod
3. **默认** - 从当前目录逐级向上查找 go.mod（与 go 命令一致，因此在子包目录中也能正常工作）

### 关于降级

当前锁定的版本要求比目标 Go 更新的工具链时，唯一"兼容"的版本可能比现在更旧。这种情况会标记为 `↓ downgrade`：

- **TUI 模式**：正常展示，由你决定是否勾选
- **`--auto` 模式**：默认跳过并打印警告，因为"自动应用全部更新"不应该悄悄把依赖往回退。需要时加 `--allow-downgrade`

`↓` 只在**确认过**更新版本因 Go 版本被排除时才出现。如果更新版本只是查不到元数据（tag 被撤回、私有模块、proxy 抽风），工具不会退而提议一个旧版本冒充降级，而是把该模块报为错误——那是网络或仓库问题，不是兼容性问题。

### 关于 v2+ 大版本

Go 把 v2 及以上的大版本放在带 `/vN` 后缀的独立模块路径下，因此 `go list -m -versions` 不会把 v2 报告为 v1 的可用版本。这类升级需要改 import 路径，属于人工决策，本工具不会自动提议。

## TUI 界面

### 四个标签页

标签页标题带条目数，如 `Update (3)`，不用逐个进去看。

#### 1. Update 标签页
- 显示有可用更新的模块，是唯一可以操作的标签页
- 空格键选择/取消，`a` 全选可见项
- 颜色表示更新类型（绿=patch, 黄=minor, 青=major, 红=prerelease），标题栏有图例
- 箭头方向表示升降：`→` 升级，`↓` 降级
- 已应用的模块显示 `✔` 并变暗，不能再次选择
- Enter 确认更新选中的模块

列表为空时会区分两种情况：过滤没匹配到（提示过滤词），或确实所有直接依赖都已是目标 Go 下的最新兼容版本。

#### 2. Require 标签页（只读）
- 显示所有直接依赖（require）
- 空格键查看详情弹窗
- 详情显示：模块信息、导入该包的 `.go` 文件列表（含测试文件）

#### 3. Indirect 标签页（只读）
- 显示所有间接依赖（indirect）
- 空格键查看详情弹窗
- 详情显示：模块信息、依赖链（`go mod why -m` 的结果，最多 15 行）

#### 4. Replace 标签页（只读）
- 显示所有 replace 指令
- 空格键查看详情弹窗
- 详情显示：原始模块和替换目标

模块路径过长时从**左侧**截断（`…/charmbracelet/bubbletea`），保留更有区分度的尾部。

### 快捷键操作

#### 导航
- `↑` / `↓` 或 `k` / `j` - 上下移动光标
- `PageUp` / `PageDown`（或 `Ctrl+B` / `Ctrl+F`）- 按屏翻页（一屏减一行，保留一行重叠）
- `g` / `G` - 跳到列表首 / 尾
- `Tab` / `Shift+Tab` - 向后 / 向前切换标签页（循环）

#### 操作
- `Space` - Update 标签页：选择/取消；其他标签页：查看详情
- `a` - Update 标签页：全选当前可见（过滤后）的模块，再按一次取消
- `Enter` - Update 标签页：确认更新（在其他标签页按下会提示切换到 Update）
- `/` - 进入过滤模式，输入关键词实时搜索（四个标签页都可用）
- `ESC` - 取消过滤（或清除已应用的过滤）/ 关闭详情弹窗
- `q` - 退出（过滤模式下 `q` 是普通字符，不会退出）
- `Ctrl+C` - 退出，任何界面都有效；**更新进行中**时第一次按下是"取消并回滚"（见下），再按一次才强制退出

**更新进行中界面只响应 `Ctrl+C`**：此时正在改写 go.mod，不接受切换状态的按键。第一次 `Ctrl+C` 会中断正在执行的 `go get` / `go mod tidy`，把 go.mod 和 go.sum 恢复到更新前的内容，然后停在"Update Cancelled"摘要页（按 `q` 退出）。如果回滚本身失败，摘要页会标出 `ROLLBACK INCOMPLETE`，此时请用 `git diff` 检查这两个文件。

#### 详情弹窗（只读标签页）
- `↑` / `↓` - 上下滚动内容
- `PageUp` / `PageDown` - 半页翻页
- `g` / `G` - 跳到顶部 / 底部
- `ESC`、`q`、`Space` 或 `Enter` - 关闭弹窗

弹窗会先立即显示模块信息，文件扫描和 `go mod why` 在后台执行，完成后自动填充（期间显示 `(loading…)`），因此打开弹窗不会卡住界面。内容超出一屏时底部显示滚动百分比；过长的行（如很深的文件路径）会自动换行，不会被截断。

#### 分析界面
- `↑` / `↓` / `PageUp` / `PageDown` - 滚动分析日志
- `g` / `G` - 跳到最早 / 回到最新一条并恢复自动跟随

向上滚动会暂停自动跟随，方便阅读历史；滚到底部或按 `G` 恢复。

### 过滤功能

1. 按 `/` 进入过滤模式（Update / Require / Indirect / Replace 四个标签页都可用）
2. 输入关键词实时筛选（大小写不敏感，匹配模块路径；Replace 页同时匹配替换目标）
3. 输入的同时可用 `↑` / `↓` / `PageUp` / `PageDown` 移动光标（`j` / `k` 此时是普通字符）；`Ctrl+U` 清空输入
4. 按 `Enter` 应用过滤并保持光标位置，按 `ESC` 取消
5. 过滤生效时标签页显示 `匹配数/总数`（如 `Update (3/40)`），按 `a` 只影响可见项，`ESC` 清除过滤

## 使用场景

### 场景 1：查看可更新的模块

```bash
go-mod-select 1.25 --dry-run
```

只查看哪些模块有更新，不执行更新操作。

### 场景 2：自动更新所有兼容模块

```bash
go-mod-select 1.25 --auto
```

跳过交互界面，自动选择并更新所有与 Go 1.25 兼容的模块（降级项默认跳过并提示）。

### 场景 3：查看依赖使用情况

1. 运行 `go-mod-select 1.25`
2. 按 `Tab` 切换到 Require 标签页
3. 选择一个模块，按 `Space` 查看详情
4. 详情弹窗显示哪些 .go 文件使用了该包

### 场景 4：分析间接依赖

1. 按 `Tab` 切换到 Indirect 标签页
2. 选择一个间接依赖，按 `Space` 查看详情
3. 详情弹窗显示完整依赖链（通过 `go mod why` 分析）

### 场景 5：检查 replace 指令

1. 按 `Tab` 切换到 Replace 标签页
2. 查看所有 replace 指令
3. 按 `Space` 查看详细说明

### 场景 6：分批更新（先 patch，再 minor）

一次全升风险高时，用过滤分批推进：

1. 先看颜色图例，绿色是 patch
2. `/` 过滤到某个组织或子系统（如 `charmbracelet`），`a` 全选，`Enter` 应用
3. 完成页按 `Enter` 回到列表，此时刚更新的显示 `✔` 并变暗
4. 换个过滤条件继续下一批

每一批都是独立的 `go get` + `go mod tidy`，中间可以随时 `q` 退出去跑测试。

### 场景 7：CI 中检查依赖是否落后

`--dry-run` 只读且不需要 TTY，适合放进流水线：

```bash
go-mod-select 1.25 --dry-run
```

注意它**始终以 0 退出**（没有"发现更新就非零退出"的模式），所以要判断结果得解析输出，例如：

```bash
if go-mod-select 1.25 --dry-run | grep -q "module(s) with a different compatible version"; then
  echo "有可用更新"
fi
```

## 工作流程

1. **启动** - 显示欢迎界面和 go.mod 信息（模块名、当前/目标 Go 版本、直接/间接依赖数）
2. **分析** - 并发检查所有**直接**依赖的兼容版本，日志实时滚动
3. **选择** - 在四标签页中选择要更新的模块
4. **更新** - 逐个 `go get`，然后 `go mod tidy`，显示进度
5. **完成** - 显示摘要；`Enter` 回到选择页做下一轮，`q` 退出

只有直接依赖参与分析和更新。间接依赖仅在 Indirect 标签页展示——它们由 `go mod tidy` 根据直接依赖推导，手动钉版本通常是错的做法。

## 注意事项

1. **只读分析** - 版本查询在临时的沙箱模块中执行，分析阶段绝不会改动你的 go.mod / go.sum
2. **备份与回滚** - 每一轮更新开始时都会**从磁盘重新快照** go.mod 和 go.sum；任一步失败时两个文件都恢复到本轮开始前的状态（原本没有 go.sum 时，新生成的会被删除）。多轮更新时，第二轮失败只回滚第二轮，第一轮已应用的升级不受影响
3. **go mod tidy** - 更新完成后会自动运行 `go mod tidy`。如果剩余依赖需要更新的工具链，tidy 可能把 go 指令抬高到目标版本之上，这时界面和 CLI 都会明确提示实际落地的版本
4. **不检查 replace** - 被 replace 的模块按原路径查询，本地 replace 的实际内容不会被检查
5. **网络依赖** - 需要网络连接来查询模块版本（走 GOPROXY）；模块缓存已预热时可离线
6. **权限** - 需要对 go.mod 和 go.sum 的写权限
7. **`--auto` 会直接改文件** - 建议先 `--dry-run` 看计划，并确保 git 工作区干净

## 常见问题

### Q: 某些模块更新失败怎么办？
A: 查看日志文件 `~/.go-mod-select/app.log` 了解详细错误信息。常见原因：
- 网络问题
- 模块已删除或重命名
- goproxy 无法访问

失败时工具已经自动回滚，工作区不会留在半更新状态。

### Q: 为什么某个模块显示的不是最新版本？
A: 因为它的最新版本要求比目标 Go 更新的工具链。工具会从新到旧回溯，找到第一个能用目标 Go 构建的版本，并在行尾标出被挡掉的版本数，如 `(2 newer need a later Go)`。日志里也能查：

```bash
jq 'select(.blocked_newer != null and .blocked_newer > 0) | {module, latest, blocked_newer}' ~/.go-mod-select/app.log
```

### Q: 某个模块报错说"could not resolve … version(s)"是什么意思？
A: 那些版本的元数据读不出来——tag 被撤回、私有模块没配 GOPRIVATE、或者 proxy 临时故障。工具刻意不在这种情况下退而提议一个更旧的版本：那会伪装成"你钉的版本需要更新的 Go"这一完全不同的结论。检查 `go env GOPROXY GOPRIVATE` 和网络后重试。

### Q: 为什么 v1 依赖没有提示升到 v2？
A: Go 的 v2+ 大版本使用带 `/vN` 后缀的独立模块路径，需要改 import 才能升级，本工具不会自动提议这类变更。

### Q: 为什么某个模块完全没出现在 Update 标签页？
A: 三种可能：它已经是目标 Go 下的最新兼容版本（那就没什么可做的）；它是间接依赖（只在 Indirect 页展示）；或者查询失败了。第三种情况在分析日志里是 `✗ Error`，具体原因看日志文件里对应模块的 WARN 记录。

### Q: 明明请求了较低的 Go 版本，为什么 go.mod 还是高版本？
A: `go mod tidy` 会在剩余依赖需要更新工具链时主动抬高 go 指令。工具会检测并明确告知实际落地的版本，但不会强行改回去——改回去只会得到一个无法构建的 go.mod。要真正降下来，得先处理那个要求高版本的依赖，用 `--dry-run` 可以看是哪些。

### Q: 如何跳过某些模块？
A: 在 Update 标签页中，不选择该模块即可。`--auto` 模式没有跳过机制，需要精细控制就用交互模式。

### Q: 更新后程序编译失败怎么办？
A: 更新过程中的失败会自动回滚。如果是更新成功但代码不兼容（例如 major 升级引入了破坏性变更），手动回滚：
```bash
git checkout go.mod go.sum
```
所以建议在 git 工作区干净时运行。

### Q: 分析很慢怎么办？
A: 正常情况下每个模块只需两次 `go list` 调用，几十个依赖也在一秒级。明显变慢通常是网络或 GOPROXY 问题——检查 `go env GOPROXY`，日志里 DEBUG 级别的 `metadata batch failed` 也是线索。

### Q: 如何查看详细的更新过程？
A: 使用 `--verbose` 参数（会透传 `go get` 的原始输出）或查看日志文件。
